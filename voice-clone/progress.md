## Notes / decisions (hand-written, preserved by the updater)

- **This directory does not train.** It prepares data, runs the baseline, scores
  every run, and shells out to `../finetune-chatterbox` for the T3 fine-tune. One
  trainer in the repo, not two - and the same checkpoint format the other
  projects use (`t3_cfg.safetensors` + `latest/`).
- **Baseline first, always.** Zero-shot Chatterbox already clones the voice from
  the reference clip. `baseline` puts a number on that *before* any GPU spend, and
  `compare` refuses to call the fine-tune a win unless the words survive it.
- **Reference clip comes from val, never train.** Otherwise the tuned model can
  have memorised it and the speaker-similarity gain is fake.
- **16 kHz mono on disk.** The voice encoder and the S3 tokenizer both consume
  16 kHz; the vocoder emits 24 kHz and is never touched by the fine-tune, so there
  is nothing to gain from storing 24 kHz WAVs.
- **Numbers are relative.** Sheng is code-switched and Swahili is agglutinative,
  so absolute CER is high for every model including the base one. `compare` looks
  at deltas, and the waveform checks (silence / clipping / runaway) need no model
  at all - they catch most real failures for free.
- **LoRA by default at this data size.** 21 min is far below the ~10 h the
  community toolkit recommends before a full fine-tune; adapters avoid wiping the
  base model's Swahili.
- **LR is deliberately low (`5e-5`, `2e-6`-`1e-5` for full FT).** The reported
  failure mode for this model family is noise or endless generation, not
  undertraining.
- **Transcripts are verbatim.** Every clip is exactly 30 s because it was cut on a
  grid, so some cuts land mid-word. Rewriting the text is what misaligns text and
  audio.
