# VoxCPM2 x Sheng (Swahili + English) LoRA - Colab pipeline

Fine-tune [`openbmb/VoxCPM2`](https://huggingface.co/openbmb/VoxCPM2) (2B, tokenizer-free
diffusion-AR TTS) to speak **Sheng** - Kenyan Swahili/English code-switching - from the
HuggingFace dataset `lyle-mlengineer/kenyan-celebs` (42 clips, one speaker `abel`,
~30 s each, ~21 min total).

Everything expensive (audio, manifests, base weights, checkpoints, logs, progress) is
written under an **artifacts root** that lives on Google Drive, so a Colab runtime
disconnect costs at most one `save_interval` of training.

```
configs/          reference YAML templates per GPU profile
notebooks/        the Colab notebook (open this first)
scripts/          colab_bootstrap.sh
src/sheng_voxcpm/ the pipeline (data, config, train, eval, export, progress, cli)
tests/            79 tests, no GPU / torch needed
progress.md       live status journal - survives a disconnect
```

## Quick start (Colab)

```bash
# 1. GPU: Runtime > Change runtime type > L4 (recommended) or A100.
# 2. Get the code somewhere under /content, then:
%cd /content/audio-speech-ai/finetune-voxcpm
!pip install -q -e .
!sheng-voxcpm doctor             # GPU / Drive / deps / model / data checklist
!sheng-voxcpm all --resume --max-hours 8
```

`all` runs `env -> data -> model -> train -> eval -> export` and **skips stages that are
already done**, so the same command is the recovery command after a disconnect.

Step by step, if you prefer:

```bash
!sheng-voxcpm env                # clone + install OpenBMB/VoxCPM (--no-deps + curated deps)
!sheng-voxcpm data               # HF dataset -> 16 kHz WAVs -> train/val JSONL
!sheng-voxcpm model              # snapshot openbmb/VoxCPM2 to a local dir
!sheng-voxcpm train --max-hours 8
!sheng-voxcpm status             # what is done, where the checkpoints are
!sheng-voxcpm eval --ab          # fixed Sheng prompts, LoRA vs base
!sheng-voxcpm export             # portable adapter package + sample wavs
```

## What the config actually does

The rendered YAML is generated by `src/sheng_voxcpm/config.py` (the `configs/*.yaml`
files are kept in sync by `tests/test_config.py`):

- `sample_rate: 16000` - the trainer asserts this against `audio_vae.sample_rate`
  (AudioVAE **encoder** input). `out_sample_rate: 48000` is the decoder and only
  affects TensorBoard audio logging. Setting 48k in `sample_rate` fails the assert.
- `num_iters == max_steps` - the first bounds the loop, the second only sizes the
  cosine schedule; keeping them equal makes "steps" mean one thing.
- Effective batch is 16 on every profile (`2x8` L4, `4x4` A100, `1x16` T4), so
  `--steps 600` means ~250 epochs over 38 clips.
- LoRA `r=32` on LM + DiT (`enable_proj: false`), lr `1e-4`, save every 100 steps.
- `distribute: false` keeps `lora_config.json` pointing at the local weights;
  `sheng-voxcpm export` rewrites `base_model` to `openbmb/VoxCPM2` for portability.

VRAM guidance from the docs is ~20 GB for VoxCPM2 LoRA. An L4 (24 GB) is the cheap
choice; A100 is faster; T4 only with `--profile t4 --allow-small-gpu` (Turing has no
native bf16, which the trainer autocasts to).

## Data notes

- The dataset is already 16 kHz-ish but clips decode at 22050 Hz, so `data` resamples
  to mono 16 kHz PCM16 (`torchaudio`, falling back to `scipy.signal.resample_poly`).
- Clips are ~30 s and kept whole: splitting them would need forced alignment, and a
  wrong transcript hurts cloning more than a long clip.
- 38 train / 4 val clips, deterministic split (`seed=1337`). Val clips are real
  held-out speech.
- `ref_audio` is off by default (single speaker, 38 clips; reference conditioning
  roughly doubles sequence length). `--ref-audio-fraction 0.35` turns it on later.

## Judging the result

`eval` synthesizes five prompts: in-domain Sheng, Swahili-heavy, English-heavy, unseen
vocabulary, and long form - plus `--ab` for the LoRA-disabled base model. Choose the
**earliest** checkpoint that sounds right and still says new words; later checkpoints
usually replay training audio (overfitting is the main failure mode).

## Disconnects

`train` resumes from `<artifacts>/checkpoints/<run>/latest` automatically
(`training_state.json`). `--max-hours` asks the trainer to checkpoint and stop just
before the Colab limit (the trainer installs its own SIGINT handler). If the runtime
dies anyway, re-run `sheng-voxcpm all --resume`: it re-mounts Drive, skips finished
stages, and continues from the last saved step. `progress.md` outside the
`BEGIN:AUTO`/`END:AUTO` markers is hand-written and never overwritten.
